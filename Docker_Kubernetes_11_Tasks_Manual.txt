E. Important differences and conventions
- macOS: Terminal/zsh. Windows: PowerShell. Commands here use single lines, so
  you do not need different multiline continuation characters.
- Paths with spaces must be quoted. Dockerfile paths such as /app are INSIDE
  Linux containers and stay the same on both operating systems.
- On Windows, enable file-name extensions in Explorer. Dockerfile must not be
  Dockerfile.txt. App.java must not be App.java.txt. Use the exact capital A.
- YAML uses spaces, not tabs. Keep indentation exactly as shown.
- The final dot in docker build means use the CURRENT folder as build context.
- A Mac and a college PC may have different processor architectures. Build
  these same source files on the college PC and push that PC's image before
  deploying to its local cluster. Do not assume an Apple Silicon-only image
  can run on an Intel/AMD college node. Reusing :latest replaces that tag's
  registry target; rebuild/push again when switching machines as needed.
- This manual uses mutable :latest tags for a simple lab workflow. It is just
  a tag name, not an automatic source-code synchronizer.
- Build directly as timothysaxena/NAME:latest to avoid a separate tag command.
  If you already have local py-t-1:latest, the equivalent extra step is:
      docker tag py-t-1:latest timothysaxena/py-t-1:latest
- Optional local-output view: Mac ls, Windows dir. These list folder contents.

F. Three Kubernetes patterns
1. Non-interactive program that prints and exits: Job + kubectl logs.
2. Program that asks for keyboard input: interactive Pod using kubectl run -it
   --restart=Never. This CLI creates a Pod; no YAML file is required for that
   route. Record its command with the task when saving to GitHub.
3. Web application that stays running: Deployment + Service + port-forward.

Jobs can also be designed to consume supplied input, but our interactive
practice uses Pods to keep the original input() and Scanner code simple.

--- BEGIN FILE CONTENT ---
import random

numbers = []

for i in range(10):
    number = random.randint(1, 100)
    numbers.append(number)

--- BEGIN FILE CONTENT ---

numbers = []
for value in values:
    numbers.append(float(value))

if numbers:
    print("Maximum:", max(numbers))
    print("Minimum:", min(numbers))

**04. JAVA - Use a parameterized constructor for addition and multiplication
==============================================================================

QUESTION: JAVA - Use a parameterized constructor for addition and multiplication
Folder: j1
Image: timothysaxena/j1:latest
Open this task folder in VS Code and its terminal before running commands.

FILE: App.java
--- BEGIN FILE CONTENT ---
import java.util.Scanner;

public class App {
    int a, b;

    App(int x, int y) {
        a = x;
        b = y;
    }

    void calculate() {
        System.out.println("Addition: " + (a + b));
        System.out.println("Multiplication: " + (a * b));
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter first number: ");
        int x = sc.nextInt();

        System.out.print("Enter second number: ");
        int y = sc.nextInt();

        App obj = new App(x, y);
        obj.calculate();

        sc.close();
    }
}
--- END FILE CONTENT ---

UNDERSTAND THE CODE
A constructor has the class name and no return type, not even void.
new App(x, y) creates an object and calls its constructor with two values.
The constructor stores the values in fields a and b. calculate() uses them.
Parentheses around (a + b) perform arithmetic before string concatenation.
Scanner reads input; nextInt() expects an integer; main() is the entry point.

class files from this source file. nextLine() accepts a full name with spaces.

**06. JAVA - Check whether an entered word or number is a palindrome
==============================================================================

QUESTION: JAVA - Check whether an entered word or number is a palindrome
Folder: j3
Image: timothysaxena/j3:latest
Open this task folder in VS Code and its terminal before running commands.

FILE: App.java
--- BEGIN FILE CONTENT ---
import java.util.Scanner;

public class App {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter a word or number: ");
        String text = sc.nextLine().toLowerCase();
        String reversed = "";

        for (int i = text.length() - 1; i >= 0; i--) {
            reversed = reversed + text.charAt(i);
        }

        if (text.equals(reversed)) {
            System.out.println("Palindrome");
        } else {
            System.out.println("Not a palindrome");
        }

        sc.close();
    }
}
--- END FILE CONTENT ---

UNDERSTAND THE CODE
A palindrome has the same characters forward and backward.
Start at length - 1, move backward using i--, and append charAt(i) to reversed.
equals() compares Java string contents; do not use == for this test.
toLowerCase() ignores case. Numeric input is treated as text, which also lets
the same code check words. Spaces/punctuation are not removed in this version.

FILE: app.js
--- BEGIN FILE CONTENT ---
const http = require("http");

const server = http.createServer((req, res) => {
    res.writeHead(200, { "Content-Type": "text/plain" });
    res.end("Welcome to DevOps Lab");
});

server.listen(3000, "0.0.0.0", () => {
    console.log("Server running on port 3000");
});
--- END FILE CONTENT ---

UNDERSTAND THE CODE

require("http") loads Node's built-in HTTP module; npm install is unnecessary.
createServer receives a function that runs for each incoming request.
req represents the request; res represents the response.
writeHead(200, ...) sets success status and plain-text content type.
res.end sends the message and ends that response, not the whole server.
listen(3000, "0.0.0.0") accepts requests on all container network interfaces.
Binding only to localhost inside the container would prevent ordinary external
container traffic from reaching this server.
EXPOSE 3000 documents the port; it does not publish the port on your computer.

12. UNDERSTAND THE FILES AND COMMANDS
==============================================================================

A. Four separate things
Source code = the program you edit.
Dockerfile  = instructions used to construct an image.
Image       = packaged program and environment; a snapshot of copied files.
Container   = a running instance created from an image.

COPY app.js . takes a copy DURING BUILD. It does not link the running container
to the source file on your computer. Existing containers do not acquire changes
when you save a file or rebuild an image with the same tag.

B. Dockerfile instructions
FROM     Choose the starting image/runtime.
WORKDIR  Choose/create the working directory INSIDE the image.
COPY     Include source files from the build context.
RUN      Execute a command while building, such as javac App.java.
CMD      Default command executed when a container starts.
EXPOSE   Document an intended container port; this alone publishes nothing.

Python: python app.py
Java:   javac App.java during build; java App when running.
Node:   node app.js
HTML:   Nginx already starts through its base-image command.

C. Docker commands and options
docker build -t IMAGE .       Build from this folder and assign an image tag.
docker run IMAGE             Create and start a NEW container from the image.
docker run --rm IMAGE        Also remove that container after it exits.
docker run -it IMAGE         Keep stdin open and allocate a terminal for input.
docker run -d IMAGE          Run in the background.
-p HOST:CONTAINER            Publish a container port on your computer.
--name NAME                 Name that container.
docker tag OLD NEW           Give an existing image another name; no rebuild.
docker push IMAGE            Upload an image to Docker Hub/registry.
docker pull IMAGE            Download an image; does not update existing containers.
docker ps                    List running containers.
docker ps -a                 Also show stopped containers.
docker image ls              List local images.
docker logs NAME             Read a container's output.
docker stop NAME             Stop a running container.
docker start -a NAME         Start an EXISTING stopped container and show output.
                             This still uses its old image; not an update method.
docker rm NAME               Remove a stopped container; not the underlying image.

D. Kubernetes objects
Pod         Smallest deployment unit; our examples contain one app container.
Job         Run a task to successful completion. Default goal: one completion.
Deployment  Maintain long-running application Pods and manage their updates.
Service     Stable network endpoint that selects matching Pods.
Node        A machine participating in the cluster, where Pods can run.
Context     Connection settings identifying the cluster/user/namespace.

Jobs: restartPolicy Never prevents restarting the failed container within its
Pod, but a Job controller can create another Pod to retry a failed task. A Job
is not an exactly-once execution guarantee for tasks with external side effects.

E. Why Deployment YAML has two spec entries
Deployment
  spec                 Desired Deployment configuration
    selector           Which Pods it manages
    template           Blueprint for new Pods
      metadata.labels  Labels put on each Pod
      spec             Desired contents of each Pod
        containers     The image(s) to run

F. Why two YAML files for the web apps
deployment.yaml says what image should keep running.
service.yaml says which Pods should receive network traffic and on which port.
These are two objects, not a requirement for two physical files: they could
be in one YAML file separated by ---. We keep separate files for clarity.

G. Port map to remember
App    Application listens on   Service port   targetPort   Browser port
n3     3000                     80             3000         8080
reg    80                       80             80           8081

docker run -p 8080:3000 maps computer port directly to a Docker container.
kubectl port-forward service/n3-service 8080:80 selects a Pod using the Service
and forwards local 8080 to its target port, using Service port 80 as the reference.
The allocated NodePort is separate, such as 30656; it is shown by kubectl get svc.
Port-forwarding does not require NodePort, but we retain NodePort to match the
teacher's example. It is useful on local setups where direct node access varies.

H. Kubernetes commands
kubectl apply -f FILE         Create/update objects described by a YAML file.
kubectl run NAME ... -it      Create an interactive Pod (with our flags).
kubectl get pods              List Pod status.
kubectl get jobs              List task completion counts.
kubectl get deployments       List managed long-running applications.
kubectl get svc               List Services and their ports.
kubectl logs POD              Show the selected Pod's container output.
kubectl logs job/NAME         Show logs from a Pod selected for that Job.
kubectl logs deployment/NAME  Show logs from a selected Deployment Pod.
kubectl describe pod POD      Inspect configuration, state, and recent events.
kubectl rollout restart ...  Trigger replacement Pods for a Deployment.
kubectl rollout status ...   Wait for the Deployment update to finish.
kubectl delete TYPE NAME      Delete the named object, not your source files.

Images and source live in different places: Docker Hub stores images; GitHub
stores code, Dockerfiles, YAML, and instructions. Pushing to one does not push
to the other.

14. COMMON ERRORS AND HOW TO RECTIFY THEM
==============================================================================

Run diagnostics in a second terminal if your first is forwarding a web port.
Read the actual error before changing code. Names below match this manual;
replace a named resource only when diagnosing a different task.

01. Cannot connect to the Docker daemon / Docker Server unavailable
Cause: Docker Desktop is stopped or still starting.
Fix: open Docker Desktop, wait until ready, then run docker version again.
If using Windows, confirm Docker Desktop is set to Linux containers.

02. docker or kubectl is not recognized / command not found
Cause: tool not installed or its location is missing from PATH.
Fix: verify Docker Desktop/tool setup; reopen the terminal after installation.
On a college computer, use the terminal/environment provided for the lab or
ask the lab administrator to complete installation. Do not change YAML for this.

03. Dockerfile not found / COPY failed: file not found
Cause: wrong folder, unsaved file, wrong capitalization, or hidden .txt suffix.
Fix: list files (Mac ls / Windows dir), open the correct task folder, and verify
Dockerfile and app.py/App.java/app.js/index.html are present. Save and rebuild.

09. ImagePullBackOff / ErrImagePull
Inspect the actual event:

    kubectl describe pod YOUR_POD_NAME
Replace YOUR_POD_NAME with the name shown by get pods; do not type the placeholder.
Likely fixes: correct the YAML image name, push the image, make its repository

A private repository needs pull credentials; this manual uses public repos.

10. no matching manifest / exec format error on another computer
Cause can be a CPU-architecture mismatch between image and node, or the wrong

11. CrashLoopBackOff for Hello Docker or another print-only program
Cause: a restart-always workload repeatedly starts a program that exits quickly.
Fix: use Job YAML for non-interactive tasks, or --restart=Never for interactive
kubectl run. Inspect logs/events; CrashLoopBackOff can also indicate code errors.
If the old standalone n1 Pod is the leftover problem:
    kubectl logs n1
    kubectl delete pod n1
Then use the n1 job.yaml from Question 07. Do not delete a managed server Pod
as a substitute for fixing its code; its Deployment would create another one.

12. Python EOFError / Java NoSuchElementException / cannot enter input
Cause: the program expects keyboard input but stdin was not attached/open.
Fix: Docker needs -it. Kubernetes uses this manual's kubectl run ... -it
--restart=Never command. Plain kubectl logs only reads output; it cannot send
answers to input() or Scanner. Recreate the failed interactive Pod and try again.

13. Kubernetes prompt is missing after interactive attachment
The first prompt may have printed before attachment. Once the container is
attached, type the expected input and press Enter. If it does not respond,
inspect kubectl get pods and kubectl logs in another terminal. Do not paste
docker/kubectl commands into the application's input prompt.

19. Docker container name is already in use
Inspect:
    docker ps -a
If it is your old stopped test container, remove that named container:
    docker rm n3-test
If running, stop it first. With --rm, stop already removes it. Do not remove an
unrelated container just because it exists. Then repeat docker run.

20. Port is already allocated / address already in use
Often an old Docker server or port-forward still owns 8080/8081.
First inspect:
    docker ps
Stop only the known test container, or press Ctrl+C in the old forwarding terminal.
Mac port inspection:
    lsof -nP -iTCP:8080 -sTCP:LISTEN
Windows PowerShell inspection:
    Get-NetTCPConnection -LocalPort 8080 -State Listen
Identify the owning application instead of terminating processes blindly.
Alternatively choose a different LOCAL port:
    kubectl port-forward service/n3-service 8090:80
Then browse http://localhost:8090. Do not change targetPort for a local-port clash.

21. Changes in app.js or HTML do not appear in the page
Cause: source, built image, Docker Hub image, and running container are separate.
Fix: save -> build -> push -> replace Pods -> wait -> restart port-forward -> refresh.
See Section 13 for exact n3/reg commands. Merely saving, pushing GitHub, running
docker pull, or reapplying identical Deployment YAML is not the whole update.

Also check WHICH app owns your browser port. In your actual n3 issue, localhost
8080 was served by an old direct Docker container even while Kubernetes ran.
Use docker ps and stop the old known container before port-forwarding to Kubernetes.
The old container's generated name will vary; do not assume a historical name.

To compare file copies for n3:
    kubectl exec deployment/n3 -- cat /app/app.js
For a direct Docker container (replace YOUR_CONTAINER_NAME):
    docker exec YOUR_CONTAINER_NAME cat /app/app.js
These read the file inside the running container. They do not modify it.
If served content is verified new but the browser is still old, reload bypassing
cache: Windows Ctrl+Shift+R; Mac Command+Shift+R.

22. Page unreachable / connection refused / Service has no usable Pods
Inspect:
    kubectl get pods -l app=n3
    kubectl get svc n3-service
    kubectl describe svc n3-service
    kubectl logs deployment/n3
Confirm the Pod is Ready, Service selector matches Pod labels, targetPort is
3000 for n3 (80 for reg), and Node listens on 0.0.0.0. Keep forwarding running.
For forwarding, use http://localhost:8080 or :8081 as printed, not HTTPS.
EXPOSE and containerPort declarations alone do not start or publish a server.

23. port-forward stops / lost connection after a rollout
Its selected Pod was replaced. Wait for rollout completion, then start the
same port-forward command again. This is expected after a Pod replacement.

24. Wait timed out / rollout has not completed
A timeout is not a diagnosis. Inspect Pods, events, and logs:
    kubectl get pods
    kubectl describe pod YOUR_POD_NAME
    kubectl logs YOUR_POD_NAME
For a restarting container, also try:
    kubectl logs YOUR_POD_NAME --previous
Resolve the reported image, scheduling, startup, or code problem. Initial
downloads can be slow; if they are progressing, wait longer and check again.

25. Deployment still uses an old cached image
Our :latest manifests default to imagePullPolicy Always when first created.
If you have edited/used other manifests, inspect the actual policy:
    kubectl get deployment n3 -o yaml
If needed, add imagePullPolicy: Always under the container, aligned with image,
apply deployment.yaml, and wait for rollout. Always does not mean continuous
updates; a new/restarted Pod is still needed after a new push to the same tag.

26. Date/time does not match India
Use the n4 source with timeZone: "Asia/Kolkata". A container may default to UTC.
Do not change the computer clock just to change a display timezone.

27. Registration form does not save users
Expected: Question 11 is a static frontend demonstration. It validates fields
in the browser and shows an alert. A real registration system needs a backend
and storage; Nginx serving HTML alone does not implement those features.

28. npm install fails / package.json missing
The Node examples here use only built-in features. Use the supplied Dockerfile,
which does not run npm install or COPY package*.json. Do not add unnecessary
dependencies just because a generic teacher example included them.

VIVA ANSWERS
What is Docker?
It packages and runs applications in containers with their required environment.

What is an image versus a container?
An image is the package; a container is an instance created from it.

What is Kubernetes?
It manages containerized workloads according to a declared desired state.

Why a Job for random numbers?
The program prints once and exits; successful completion is the desired result.

Why -it?
It keeps input open and allocates a terminal so we can interact with the program.

Why Deployment and Service for a website?
Deployment maintains the running server Pods. Service provides a network
endpoint and selects the Pods that receive traffic.

Why not a Service for a print-only program?
It does not listen for network requests; its output is read through logs.

Why is Java's Dockerfile different?
It uses RUN javac App.java to compile, then CMD java App to execute at startup.

What does latest mean?
It is the default tag when none is supplied. It does not make running
containers update automatically when source files or the registry image change.

What is the difference between GitHub and Docker Hub?
GitHub stores the source and configuration; Docker Hub stores built images.

Does the HTML registration page save accounts?
No. It is a static frontend with browser validation, served using Nginx.
